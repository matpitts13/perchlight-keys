# Tech debt

- **SES, Mailgun and Postmark aren't wired** (`src/lib/mail/index.js`). The SDD names perchlight-list's four providers; v0.1 ships Resend only. Fix: copy `ses.js` (+ `sigv4.js`), `mailgun.js` and `postmark.js` from perchlight-list `src/lib/senders/` (standard sends only) and add cases to `getSender`. Found while building v0.1 (2026-11-12).
- **Should-haves not built in v0.1:** Turnstile on the resend and claim forms; Godot and C++ verifier samples; the hosted "Manage my devices" page (buyers free devices from the app, or by activation id through `/v1/deactivate`); seat transfer; the outgoing `HEARTBEAT_URL` after a sweep.
- **A refund of an upgrade order isn't linked to the upgraded licence.** An upgrade purchase (`{ "edition": "pro", "upgrade": true }`) changes the existing licence's edition but registers no ref for the upgrade order, so its refund waits as `pending_target` and is dropped after 7 days (shown in the app). Fix: insert a `license_refs` row for the upgrade order pointing at the licence, and make its refund a downgrade rather than a revoke.
- **Stripe subscription events are applied in arrival order** (`src/routes/webhooks.js`). A late `customer.subscription.updated` (active) can undo a newer `.deleted`. Fix: store the event's `created` per licence and skip older events. Found in the v0.1 review (2026-11-12).
- **Revocation list paging at second precision** (`src/routes/licensing.js`). `next_since` is in seconds with `>=`; more than 1,000 revocations in one second never advances the page. Fix: cursor on (revoked_at, id). Found in the v0.1 review.
- **No throttle on failed admin auth** (`src/routes/admin.js`). The 16-character minimum is the only guard against guessing. Fix: an isolate-memory counter per IP hash on 401s. Found in the v0.1 review.
- **Resend with RESEND_REISSUE=1 re-issues keys one by one** (`src/lib/deliveries.js` `keyFor`), up to 20 licences, each a D1 write; a large list can run out of budget mid-build and waste a retry attempt (no loop). Fix: batch the re-key updates. Found in the v0.1 review.
- **`POST /api/rekey` reports `more: true` forever if undecryptable rows fill a batch.** Fix: skip rows already counted as failed (cursor by id). Found in the v0.1 review.
